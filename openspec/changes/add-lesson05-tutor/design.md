# Design

MySQL 新增 `tutor_agents`、`tutor_skills`、两张绑定表、`tutor_conversations`、`tutor_messages`。会话锁定创建时选定的智能体，但每轮重读该智能体当前绑定。服务端从 Bearer token 查用户及班级；教师写操作另校验 CSRF，跨班或跨用户资源按不存在返回 404。

技能保存教师编辑或导入的完整 Markdown 原文，以第一个一级标题提取技能名称，原文整体作为模型引导；旧中文字段文件保持兼容。单个绑定的 Markdown 技能默认使用；多个技能按已有适用条件词法得分选择，同分取较小 ID。名称包含「解题引导」时，系统消息要求只提示下一步，不给最终答案。

每次提问先落库；检索使用第 4 课服务，SQL 将材料限制在本班智能体绑定 ID，向量候选也再过滤。最多保留四条证据，编号连续。系统消息只放角色、技能、引用边界；资料正文进用户消息。模型上下文取最近六条消息，每条最多 500 字。无证据时仍调用对话模型，并删除无效 `[n]` 引用。

POST 消息接口返回 SSE：`meta` 先带技能及引用，`delta` 仅带新增片段，持久化后 `done` 给消息 ID，流开始后的故障发 `error`。Nginx 关闭响应缓冲并放宽读取超时。OpenAPI 使用仓内生成脚本更新并作为静态文件嵌入 Go 服务；Swagger UI 资源一并本地提供。`apitest/` 通过同一 Compose 项目的 MySQL 校验返回值和持久化结果。
