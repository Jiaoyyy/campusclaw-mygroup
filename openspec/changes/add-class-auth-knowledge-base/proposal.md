# Proposal

## Why

项目需要一个可运行的教学材料知识库，使教师和学生能登录并使用本班材料，同时在服务端阻止学生上传及跨班访问。当前仓库只有 OpenSpec 配置、没有应用代码或既有规格，本变更建立首个端到端应用基础。

## What Changes

- 教师、学生使用账号密码登录；未登录访问受保护页面转到登录页，API 返回认证错误。
- 每个账号暂时只属于一个班级；服务端根据已认证账号执行角色和班级检查，拒绝学生上传和跨班材料访问。
- 教师上传 TXT 或 Markdown 材料后提取正文，持久化原文件、材料记录和本班知识库正文；本班教师和学生可在列表中查看材料，并经授权查看正文、下载文件。
- 上传校验或正文入库失败时返回明确错误，清理文件和数据库残留；材料列表只显示成功入库的真实记录。
- 密码只存哈希；密钥通过服务端环境变量注入，不进入源码、前端或日志。
- 提供 Docker Compose 启动、持久化存储及公开的 GET /health。
- 首期通过服务端幂等种子流程预置 A/B 两班及教师、学生账号，口令由环境变量提供；不包含自行注册、班级管理或多班级账号。首期材料支持 UTF-8 TXT 和 Markdown。

## Non-goals

- 本课不实现向量检索、全文检索、RAG 问答、对话助手或基于材料自动生成答案；本班材料列表筛选不属于跨班或全文检索。
- 不实现作业提交与批改，也不扩展到教学评价流程。
- 不实现 SSO、公开注册、多班级账号或生产环境高可用（HA）；账号与班级由服务端预置，首期采用单班级归属与单实例部署。
- 不实现 PDF、DOCX、扫描件 OCR、材料编辑或删除。

## Capabilities

### New Capabilities

- `user-auth`: 账号密码登录、安全会话、页面和 API 认证、密码安全存储。
- `class-access-control`: 单班级归属、教师上传权限、材料和知识库正文的服务端班级隔离。
- `teaching-knowledge-base`: TXT/Markdown 上传、材料列表和读取、正文提取与持久化。
- `application-runtime`: Compose 部署、服务端密钥配置、持久化与健康检查。

### Modified Capabilities

无；尚无已有规格。

## Impact

新增 React/TypeScript/Vite 前端、Nginx 入口、Go API、MySQL 迁移和文件存储；新增认证、材料上传/列表/详情/下载及健康检查接口。Compose 与集成测试覆盖两类角色、两个班级、重启持久化及上传/正文入库失败路径。不存在需要兼容的已有接口或数据迁移对象。
